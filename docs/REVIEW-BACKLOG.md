# Бэклог по итогам ревью (сентябрь 2026, версия 0.2.1)

Ревью всего репозитория. На момент ревью все 39 тестов проходили
(`node --test tests/*.test.cjs`). Код в рамках ревью не менялся.

Статусы: `[ ]` — открыто, `[x]` — сделано (укажите коммит), `[-]` — отклонено (укажите причину).
Номера строк относятся к коммиту `e28e8ec` и могут сместиться.

Для сверки поведения использовался init-скрипт апстрима
[DPITrickster/ByeDPI-OpenWrt](https://github.com/DPITrickster/ByeDPI-OpenWrt)
(`byedpi/files/byedpi.init`). Важные факты из него:

- при непустом `byedpi.main.cmd_opts` все остальные UCI-опции игнорируются, строка
  разбивается по словам: `procd_set_param command $PROG $OPTS`;
- инстанс запускается только при `byedpi.main.enabled=1` (`section_enabled`);
- ciadpi работает от `nobody` (`procd_set_param user nobody`) с `respawn`;
- без `-i`/`-p` ciadpi слушает `0.0.0.0:1080`;
- ключ `options` апстрим не читает, это только legacy-копия.

## Существенные

- [ ] **1. Выбор пресета затирает адрес и порт SOCKS.**
  В пресетах из `root/usr/share/byedpi-luci/strategies.txt` нет `-i`/`-p`, а
  `apply_strategy` (`root/usr/libexec/byedpi-luci:198`) заменяет `cmd_opts` целиком.
  Пример: у пользователя `-i 127.0.0.1 -p 1081 ...` под Podkop. После «Выбрать пресет →
  Сохранить» Podkop молча ломается, а SOCKS начинает слушать `0.0.0.0`.
  Что сделать: при применении переносить listener-флаги (`-i`, `-p`, `--ip`, `--port`,
  включая формы `-p1081` и `--port=1081`) из текущей строки, если в новой их нет.
  Разбор уже есть в `prepare_strategy` (`root/usr/libexec/byedpi-luci-test:35`).
  Другой вариант — отдельные поля «адрес/порт» в UI. Нужен тест.

- [ ] **2. UCI `byedpi.main.enabled` не учитывается в статусе.**
  `json_status` (`byedpi-luci:21`) смотрит только на `/etc/init.d/byedpi enabled`.
  При `enabled=0` инстанс не стартует, а UI показывает «Автозапуск включен».
  Кнопка «Запустить» тогда падает с непонятным «не перешёл в ожидаемое состояние».
  Нужно добавить поле в `status` и строку в `diagnostics`, а при ошибке `service start`
  подсказывать причину.

- [ ] **3. Диагностика привязана к `127.0.0.1:1080`** (`byedpi-luci:125-151`).
  Порт нужно брать из `cmd_opts`, по умолчанию 1080. Сравнивать с ожидаемым
  `proxy_string` Podkop на этом же порту. Если `/etc/config/podkop` нет, проверки
  Podkop пропускать или показывать нейтрально, а не как две красные «Ошибки».

- [ ] **4. Права в ACL** (`root/usr/share/rpcd/acl.d/luci-app-byedpi.json`).
  `exec` хелпера лежит в секции `read`, поэтому пользователь только с правами на чтение
  может вызвать `apply`, `service restart` и `start-autotest`.
  Что сделать: убрать exec из `read`. Если нужен просмотр для read-only пользователей,
  разделить хелпер на читающий и пишущий или проверять действие.
  Лишние права: `uci` write на `podkop` и `ubus service list` фронтенд не использует.
  Перед удалением проверить, что меню (`depends.uci.byedpi`) продолжает работать.

- [ ] **5. Логи тестовых ciadpi копятся в RAM.**
  `"$CIADPI" ... >"$WORK/proxy_$active_slot.log"` (`byedpi-luci-test:77`) пишет в
  `/tmp`, то есть в tmpfs, и эти логи нигде не читаются; `worker.log` тоже.
  Фильтр отсекает `--debug`, но пропускает короткий `-x`. С `-x 2` за 60-минутный тест
  лог может занять десятки МБ на роутере со 128 МБ.
  Что сделать: писать в `/dev/null` или хранить только хвост; добавить `-x`/`--debug`
  в список отбрасываемых ключей `prepare_strategy`.

- [ ] **6. Тестовые ciadpi запускаются от root, рабочий — от `nobody`.**
  Для одинаковых условий теста и минимальных привилегий запускать кандидатов от
  `nobody`. Проверить, что учёт PID и starttime (`pid_stamp`/`owned_alive`) по-прежнему
  относится к самому ciadpi, а не к обёртке.

## Удобство интерфейса

- [ ] **7. Список пресетов** (`htdocs/.../byedpi/main.js:237`).
  Если текущая стратегия не из списка, браузер показывает выбранным пресет #1, хотя в
  textarea другая строка. Выбрать #1 нельзя: `change` не срабатывает.
  Нужна первая пустая опция «— своя стратегия —», выбранная по умолчанию. Список
  также стоит синхронизировать при вводе в textarea и в `updateStatus`.

- [ ] **8. Открытие страницы ждёт диагностику** (`main.js:627`, `load()`).
  В `diagnostics` curl с `-m 8` плюс `netstat`; при неработающем SOCKS страница
  открывается около 10 с. Диагностику загружать при первом открытии её вкладки.

- [ ] **9. Первичный отбор долгий.**
  86 кандидатов × (1 с на старт + 2 запроса до 8 с) — до ~25 мин при плохом канале,
  и это до выбранных «5/15/60 минут». Варианты: меньший `--max-time` на этапе
  `screen`; показывать ETA и число оставшихся кандидатов. При изменении логики
  отбора обновить README и тесты.

- [ ] **10. Проверка YouTube** (`probe`, `byedpi-luci-test:128`).
  - `HEAD https://www.youtube.com/` в части регионов отдаёт 302 на consent, и тогда
    падают все кандидаты. Рассмотреть `https://www.youtube.com/generate_204` (тот же
    SNI); перед заменой проверить, что он стабильно отдаёт 204.
  - `googlevideo.com`, где обычно и тормозит видео, не проверяется. Рассмотреть
    запрос к `redirector.googlevideo.com`. Адрес закреплять через DoH так же, как
    для остальных целей.

- [ ] **11. DoH только Google и Cloudflare** (`resolve_targets`, `byedpi-luci-test:101`).
  Если провайдер режет 8.8.8.8 и 1.1.1.1, подбор не стартует. Добавить третьего
  провайдера с JSON API и закреплённым IP, проверку сертификата сохранить.

## Мелочи и чистка

- [ ] **12. `install.sh` при запуске через `wget ... | sh`.** `$0` равен `sh`, и
  `find_local_source` (`install.sh:132`) смотрит в текущий каталог. Если пользователь
  стоит в старом клоне репозитория, установится старая локальная копия вместо `main`.
  Локальный источник использовать только когда `$0` — реальный файл `install.sh`.
- [ ] **13. Разбор ответа GitHub API через `sed`** (`find_byedpi_package_url`,
  `install.sh:236`). `jsonfilter` уже обязателен, лучше
  `jsonfilter -e '@.assets[*].browser_download_url'`. Для `apk add --allow-untrusted`
  нет проверки sha256; можно закрепить версию и хеш.
- [ ] **14. Фиксированные временные файлы** `/tmp/byedpi-luci-service.json` и
  `/tmp/byedpi-luci-curl.log` (`byedpi-luci:23,132`). Опрос идёт каждые 5 с на
  каждую вкладку, и параллельные вызовы гоняются за одним файлом. Лучше использовать
  переменные или `mktemp`.
- [ ] **15. Зависший lock `/tmp/byedpi-luci-test-v2.start`.** Если держатель убит
  SIGKILL (например, по тайм-ауту rpcd), trap не срабатывает, и все действия
  блокируются до перезагрузки. Хранить PID и starttime внутри каталога блокировки
  и снимать чужую мёртвую блокировку.
- [ ] **16. Мёртвый код и данные:** `domains.txt` и `DOMAINS_FILE`, `proxytest.results`
  (README сам говорит, что не используется), пустой `score` в `list_strategies`,
  неиспользуемый параметр `renderTesterTab(status)`. При удалении обновить
  `INSTALL_PATHS` и `chmod` в `install.sh`, а также `tests/installer.test.cjs`.
  Версия `0.2.1` продублирована в `Makefile` и `main.js`.
- [ ] **17. Нет CI.** Тесты запускаются под `dash`, а на роутере работает busybox
  `ash`. Добавить GitHub Actions: `node --test tests/*.test.cjs`, shellcheck (`-s sh`)
  и прогон с `TEST_SHELL="busybox sh"`.
- [ ] **18. Нет перевода.** Русские строки используются как msgid, английского
  интерфейса нет. Низкий приоритет.
- [ ] **19. Мелкая несогласованность:** `clean_lines` в `byedpi-luci` вырезает `//...`,
  а список кандидатов в `byedpi-luci-test` — только `#`. Выровнять.

Предложенный порядок: 1–8 и 14 одним набором с тестами, затем 17 (CI), остальное — по желанию.
