# luci-app-byedpi

LuCI-страница для управления ByeDPI на OpenWrt.

Добавляет раздел:

```text
Службы -> ByeDPI
```

Прямой путь:

```text
/cgi-bin/luci/admin/services/byedpi
```

## Что умеет

- показывает статус `ciadpi`, init-скрипта, UCI-конфига и SOCKS-порта;
- запускает, останавливает и перезапускает ByeDPI;
- сохраняет аргументы `ciadpi` в `byedpi.main.cmd_opts` и `byedpi.main.options`;
- дает выбрать готовую стратегию или вписать аргументы вручную;
- проверяет доступ через `socks5://127.0.0.1:1080`;
- автоматически отбирает и повторно проверяет стратегии на текущем роутере;
- сравнивает ошибки, медленные ответы, разброс задержек и скорость тестовой загрузки;
- проверяет кандидатов отдельно от рабочего сервиса и сохраняет результаты при закрытии страницы;
- при установке может добавить секцию `podkop.byedpi`.

## Требования

- OpenWrt с LuCI;
- `curl` с поддержкой HTTPS и актуальный `ca-bundle` для проверки стратегий;
- `curl` или `wget` для скачивания установщика;
- стандартные компоненты LuCI/OpenWrt: `uci`, `jsonfilter`, `jshn.sh`, BusyBox `netstat`.

Если ByeDPI еще не установлен, установщик попробует поставить пакет `byedpi`
из релизов [DPITrickster/ByeDPI-OpenWrt](https://github.com/DPITrickster/ByeDPI-OpenWrt).

## Автоматическая установка и обновление

Для первой установки и последующих обновлений используется одна команда по SSH:

```sh
wget -qO- https://raw.githubusercontent.com/moz9/luci-app-byedpi/main/install.sh | sh
```

При первой установке установщик поставит нужные файлы и зависимости, запустит
новый ByeDPI и подготовит интеграцию с LuCI. При обновлении существующие
настройки и состояние служб сохраняются. Все блоки ниже — пояснения и
дополнительные варианты.

Если на роутере нет `wget`, можно выполнить ту же установку через `curl`:

```sh
curl -fsSL https://raw.githubusercontent.com/moz9/luci-app-byedpi/main/install.sh | sh
```

Что делает установщик:

- ставит ByeDPI, если нет `/usr/bin/ciadpi` или `/etc/init.d/byedpi`;
- устанавливает недостающие `curl` и `ca-bundle` через `opkg` или `apk`;
- включает и запускает новый ByeDPI, а у уже установленного сохраняет состояние;
- обновляет файлы LuCI и очищает серверный кэш без перезапуска веб-сервера;
- если найден Podkop, создаёт секцию `podkop.byedpi`, только когда её ещё нет;
- перед заменой сохраняет файлы и конфигурацию в
  `/etc/luci-app-byedpi/rollback.tar.gz` (одна копия до последнего запуска);
- при ошибке установки восстанавливает эти файлы и конфигурацию;
- не обновляет файлы во время подбора и не коммитит чужие несохранённые изменения UCI.

Секция Podkop по умолчанию:

```sh
config section 'byedpi'
	option connection_type 'proxy'
	option proxy_config_type 'url'
	option proxy_string 'socks5://127.0.0.1:1080#byedpi'
	option resolve_real_ip_for_routing '1'
```

Если `podkop.byedpi` уже существует, установщик сохраняет её целиком, включая
списки доменов, подсетей, адрес прокси и параметры маршрутизации. Списки
`community_lists` пользователь выбирает сам в Podkop. Перезапуск Podkop нужен
только при создании новой секции.

Существующий бинарный пакет ByeDPI эта команда сохраняет; обновляются
LuCI-приложение и автоподбор. Установка отсутствующих зависимостей выполняется
штатным менеджером пакетов и не отменяется при откате файлов приложения.

## Автоподбор стабильной стратегии

В разделе **Службы → ByeDPI → Автоподбор** нажмите **Подобрать стратегию**.
Рейтинг рассчитывается заново на этом роутере: регион, провайдер и текущие
условия подключения учитываются фактическими измерениями. Готового общего
победителя для всех роутеров нет.

Перед отбором тестер получает реальные IPv4-адреса трёх тестовых сайтов через
DNS-over-HTTPS Google, при недоступности — Cloudflare. DNS-запросы также
проверяют сертификат сервера; настройки DNS роутера не меняются. Если реальные
адреса получить не удалось, подбор завершается с ошибкой подготовки.

1. Текущая стратегия и до 63 уникальных пресетов проходят первичный отбор.
   Для каждого выполняются HTTPS HEAD-запросы к YouTube и Google.
2. До трёх лучших кандидатов проверяются повторно в течение 5, 15 или 60 минут
   после отбора. Прошедшая отбор текущая стратегия включается для сравнения.
3. Во время повторной проверки каждый кандидат использует свой постоянный
   экземпляр `ciadpi`. Запросы выполняются последовательно, порядок кандидатов
   меняется между кругами. На каждом круге выполняются два запроса к каждой
   цели, что проверяет повторные подключения и работу кэша без перезапуска.
4. В первые восемь кругов каждый кандидат дополнительно загружает 1 МиБ
   тестовых данных Cloudflare: суммарно до 24 МиБ плюс служебный трафик.
5. Кнопка **Выбрать** переносит аргументы в настройки. Применение выполняется
   отдельной кнопкой **Сохранить и перезапустить**. При неудачном запуске
   приложение пытается вернуть прежнюю конфигурацию и сообщает результат возврата.

Для проблемы, возникающей через 30–60 минут, используйте режим **60 минут**.
Первичный отбор занимает дополнительное время. Последний круг выполняется
полностью, поэтому итоговая длительность может немного превышать выбранную.
Короткий режим позволяет отсеять очевидные ошибки, но не проверяет сбой через час.

Рейтинг строится по доле ошибок, доле успешных запросов с задержкой от 1,5 с,
95-му процентилю задержки, разбросу относительно медианы и минимальной скорости
тестовой загрузки. В повторной проверке задержка и разброс сравниваются
диапазонами по 100 мс: внутри одинаковых диапазонов приоритет получает лучшая
минимальная скорость. Это уменьшает влияние случайной разницы в несколько
миллисекунд. При равной скорости сравниваются точные задержки и медиана. Порог 1,5 с — критерий этого тестера, его нельзя
трактовать как границу работоспособности всех сайтов и всех подключений.

Рекомендация выдаётся только после завершения проверки: минимум три круга,
12 HTTPS-запросов, обе цели, успешная тестовая загрузка, отсутствие ошибок и
95-й процентиль менее 1,5 с. Если условия не выполнены, рейтинг остаётся
доступен, но «стабильный победитель» не назначается. Поставляемые ранее оценки
из `proxytest.results` больше не используются для ранжирования.

### Что именно проверяется

- Все кандидаты используют одинаковые реальные IPv4-адреса, закреплённые
  на время запуска. FakeIP `198.18.0.0/15` и локальные адреса не допускаются:
  иначе Podkop может повторно направить запрос через рабочую стратегию.
  Перенаправления HTTP не выполняются, чтобы не уйти на незакреплённый адрес.
- Проверяется **HTTPS через локальный SOCKS**, включая TLS, HTTP-статус и
  полноту тестовой загрузки. HTTP 403/404/500 и ошибки сертификата не засчитываются
  как успешное открытие сайта. Автоматических повторов, скрывающих сбои, нет.
- Задержка HTTPS не является ICMP-пингом. Показатель 3171 мс при обычных 188 мс
  может соответствовать трёхсекундному ожиданию с последующим переключением
  стратегии, но одни цифры не подтверждают причину.
- Загрузка Cloudflare сравнивает передачу данных через прокси. Она **не измеряет
  скорость googlevideo.com** и не гарантирует работу конкретного видео, QUIC
  или маршрута устройства через Podkop. После применения проверьте реальное
  видео и перемотку на устройстве; при исходном сбое — не менее часа.
- Результаты относятся к этому роутеру, провайдеру и периоду проверки.
  Если ни один кандидат не проходит тест, причиной может быть и DNS, WAN,
  доступность тестовых адресов или нагрузка, а не сама стратегия.
- Тестер использует существующий исходящий маршрут самого роутера. Если весь
  его трафик уже проходит через VPN, это также влияет на измерения.

### Изоляция и остановка

Тестер не изменяет UCI, не переключает Podkop и не перезапускает рабочий ByeDPI.
Кандидаты слушают только `127.0.0.1` на свободных портах `2080–2089`, с лимитом
32 подключения на экземпляр. Одновременно могут работать до трёх тестовых
экземпляров; это требует дополнительной памяти и сетевого трафика.

Настройки адреса, порта, daemon и выходных файлов исключаются из тестового
запуска. Прозрачный режим, неоднозначные сокращения длинных ключей и shell-
кавычки не поддерживаются тестером. Стратегия никогда не исполняется через `eval`.

Кнопка **Остановить** завершает подбор после текущего запроса (обычно до 8–12 с).
Работа продолжается при закрытии LuCI; при повторном открытии показывается
текущее состояние. Прерванный или остановленный запуск не выдаёт рекомендацию.
Результаты хранятся в `/tmp/byedpi-luci-test-v2` до следующего запуска или
перезагрузки роутера. Пакеты сборки и скрипт установки обеспечивают зависимости
`curl` и `ca-bundle`.

## Проверка разработки

На компьютере с Node.js, POSIX shell и awk:

```sh
node --test tests/*.test.cjs
```

Тесты проверяют ранжирование с таймаутами и выбросами, HTTP-ошибки, неполные
загрузки, защиту от FakeIP, безопасный запуск, повторное использование процесса
и его очистку, сохранение настроек при обновлении и возврат после ошибки.
Они не заменяют проверку пакета на OpenWrt и часовую проверку у провайдера.

## Обновление

Остановите выполняющийся подбор, затем повторно запустите установщик:

```sh
wget -qO- https://raw.githubusercontent.com/moz9/luci-app-byedpi/main/install.sh | sh
```

После обновления откройте страницу ByeDPI заново. Если браузер показывает старый
интерфейс, обновите её с очисткой кэша (`Ctrl+F5`).

## Удаление

```sh
wget -qO- https://raw.githubusercontent.com/moz9/luci-app-byedpi/main/uninstall.sh | sh
```

Удаление убирает файлы `luci-app-byedpi`. Если установщик сам создавал
`podkop.byedpi`, секция удаляется. Если установщик сам ставил пакет ByeDPI,
пакет удаляется. Если ByeDPI был установлен заранее, пакет остается.

Принудительно удалить секцию Podkop и пакет ByeDPI:

```sh
wget -qO- https://raw.githubusercontent.com/moz9/luci-app-byedpi/main/uninstall.sh | REMOVE_PODKOP_BYEDPI=1 REMOVE_BYEDPI=1 sh
```

## Сборка пакета

Скопируйте каталог в OpenWrt build tree или package feed:

```sh
make package/luci-app-byedpi/compile
```

OpenWrt 25.12+ собирает `.apk`, старые версии собирают `.ipk`.
